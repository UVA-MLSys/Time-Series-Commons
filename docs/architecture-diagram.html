Design Inspiration
How the new architecture mirrors the IndyCar project
The IndyCar real-time analytics pipeline from Indiana University uses a pub/sub event-driven architecture to stream telemetry from 33 race cars to live dashboards. The new Time Series Commons broker is deliberately modelled on the same pattern — each component in our system has a direct structural equivalent in theirs.

One deliberate difference
IndyCar uses MQTT (ActiveMQ Apollo) as its broker — a dedicated message queue designed for high-frequency telemetry (33 cars × ~10 Hz). Time Series Commons uses PostgreSQL LISTEN/NOTIFY instead, because the event volume is far lower (hundreds of dataset updates per day, not thousands per second) and PostgreSQL is already the primary store. This avoids running a second infrastructure service while preserving the same architectural separation: the broker never talks directly to the listener — it only writes to the DB and lets the notification layer do the routing.
